# 案例 dtk-06：风险预审——实施前抓到 6 个方案自带 P0

> 项目：[dtk 申论格子纸](https://github.com/isxulong/dtk)（2026-10-15，白屏优化实施前；本案例发生于实施前，无独立 commit 与版本号，实施锚点见 `case-dtk-05`：commit 23a20807、版本 20261015a）。这是「方案定稿后、实施前强制风险预审」规矩的出处——本手册最推崇的一个环节。

## 背景

白屏优化方案经红蓝对抗四轮终裁定稿（见 `case-dtk-05`）。用户问了一个关键问题：**「分析修复方案可能带来的错误」**——方案越有效，越要先想清楚它会怎么出错。

## 当时发生了什么

两路独立风险审查并行（都基于真实源码逐行核查，不是空想）：

- **实现层失败模式**（质检视角）：逐项回答「这个改动在什么条件下会出错、出错的用户可见现象是什么」；
- **方案层风险**（架构视角，由方案提出方自审）：兼容性矩阵、部署爆炸半径、回滚可逆性、被裁判否决口径的防回潮。

审查结论：**方案方向无需返工，但抓到 6 个方案自身会引入的 P0 错误**——不规避的话，会把「白屏」换成更伤信任的新故障。

## 六个 P0 与规避设计（每一条都是教学案例）

| # | 方案项 | 自带错误 | 触发条件与用户可见现象 | 规避设计 |
|---|---|---|---|---|
| 1 | 加载看门狗 | 看门狗写进模块里会**随模块一起死** | 模块加载挂起时整个模块不执行，写在里面的超时检测根本不运行——兜底形同虚设 | 看门狗用**独立经典脚本**放 head（非 module）；就绪标志设在模块体末尾 |
| 2 | 失败重试 | 重试 = 重新初始化 → **粘贴文本翻倍** | 监听器挂双份，一次粘贴插入两遍 | 重试**只允许** `location.reload()`；超时阈值 ≥10s 防慢网误报 |
| 3 | 范文写进 HTML | JS 就绪前用户打的字被初始化覆盖——**静默丢字** | 输入区从 HTML 解析完就可编辑，但此时打的内容不保存，init 拿范文整段盖掉 | init 改三态语义（无存档→范文；有存档→存档；当前内容与范文不一致且非空→保留用户输入照常渲染入撤销栈），**与范文落 HTML 同批上线不得单做** |
| 4 | 版本号 12 处同步 | 漏一处 + 一年缓存 = **新旧模块混血，最长一年不可自愈** | 新引擎配旧标点规则：无报错、只影响老访客、开发者复现不了 | version-sync 测试门禁（断言 12 处一致）+ 一键 bump 脚本机器改 |
| 5 | 范文双数据源 | HTML 与 JS 两份**静默漂移** | 改了 JS 那份忘改 HTML 那份，所有测试照样全绿，只在模块加载失败时暴露旧范文 | 测试加双源逐字节比对 |
| 6 | init 代码迁移 | 丢异常保护 → **全部按钮变死键** | 隐私模式禁用本地存储等场景中断整个模块 | 按钮挂载移到 init 之前 + 保留 try/catch；现有测试可拦截 |

另有两个设计裁决：范文形态选「静态文本写进输入区」否决「预渲染格子」（后者每次改引擎都要重生成 400 格 HTML，漂移面高两个数量级）；回滚口径定为「一年缓存上线后 JS 只能向前回滚（发新版本号）」。

## 怎么验证预审抓得对不对

6 条规避全部转化为实施任务书的**硬性验收项 + 自动化测试门禁**，质检逐项独立验证生效，包括三个硬场景：

- 看门狗在模块被杀死时照样 10 秒触发；
- 重试只有整页刷新（代码审查确认无重新初始化路径）；
- 就绪前真实打字逐字保留不丢（旧版同样操作会被静默盖掉）；
- version-sync 门禁对抗性验证：故意改错版本号 / 删 preload / 改范文一字，三类破坏全部立刻红。

## 沉淀的规则

1. **风险预审是强制环节，不是可选项**：方案定稿（对抗终裁）后、实施前，必须回答「这个方案自己在什么条件下会出错」。成本参照：本例的代价是把「约 20 行改动」变成「小改动 + 一组测试门禁」。
2. **预审分两路**：实现层失败模式（什么条件下出错、用户看到什么）+ 方案层风险（兼容性、爆炸半径、回滚）——一路抓不到另一路的盲区（#3 静默丢字就是方案层独捕）。
3. **预审成果的归处是门禁**：抓到的每个 P0 必须三选一落实——规避设计 / 测试门禁 / 回滚预案，大多数能固化成自动化测试。
4. **「会一起死」模式**：兜底机制不能依赖它要兜底的对象（看门狗不能写进被看守的模块里）。推广：监控不能和被监控服务同生死、备份不能和主库同机房。
5. **「静默漂移」模式**：双数据源、多处同步的值，默认一定会漂，唯一解法是机器比对（测试断言），人肉纪律无效。

## 这条规则后来怎么用

- version-sync 门禁 + bump 脚本成为 dtk 永久工程资产：「漏改版本号」这类事故发版必炸（测试红），不再靠人记。
