# 规则 04：发布与部署纪律

> 「代码改完了」和「用户能用了」之间隔着一整套纪律。本篇覆盖：推送验证、版本同步、缓存与回滚、部署配置。

## 一、推送三段验证（少一段不算发布完成）

**第 1 段 · 推送前**
- 敏感信息扫描零命中（本地 + 远端 tarball 双扫），模式见 `checklists/secrets-scan-checklist.md`。
- 推送前先确认远端 HEAD 未漂移（GET 一次确认仍是预期值），漂移则先报告，不硬推。
- 用 fast-forward，不 force push。

**第 2 段 · 推送后**
- **逐文件远端比对**：拉取远端每个文件与本地逐字节一致（不只比对文件清单和大小）。真实记录：一键排版 11/11、白屏优化 16/16 逐字节一致才算过。
- 抽查关键不变量：版本号全部同步点一致、新增文件确实在 tree 中且被正确引用。

**第 3 段 · 部署后线上核验**
- 用 curl/无头浏览器对**线上真实地址**核验，不是看部署平台的「成功」绿勾。白屏优化上线时的核验五项（可复用为模板）：
  1. HTML 响应**不得**含 immutable/长缓存（HTML 永远不进强缓存）；
  2. 静态模块响应必须含预期的长缓存头；
  3. 同一 URL 二次请求缓存命中（HIT）；
  4. 逐个模块核响应头，既有安全头（CSP/HSTS 等）仍在；
  5. 线上实际渲染抽查（DOM 内容与范文正常）。
- 网络受限环境的备用通道：当 git 端点不可用时，走平台提供的 API（如 Git Data API：blobs → tree → commit → update ref），不因通道故障放弃验证步骤。

## 二、版本同步：机器断言，不靠人记

**规则**：凡是「同一个值出现在多处」的东西——版本号、引用查询串、双数据源、成对配置——必须：
1. 有一处**唯一权威源**（如 package.json 的 version）；
2. 有一个**同步测试**断言全部出现处一致（进 CI）；
3. 有一个**一键 bump 脚本**机器改全部位置。

**为什么**：dtk 白屏优化把版本号同步点扩到 12 处；漏改一处 + 静态资源一年期缓存 = 用户拿到「新 HTML + 旧 JS」的新旧模块混血，**无报错、只影响老访客、开发者复现不了、最长一年不可自愈**。version-sync 测试故意破坏三类（改错版本号 / 删 preload / 改范文一字）必须全红才算门禁有效。

**双数据源同理**：同一份内容落在两处（如范文同时写进 HTML 和 JS），必须加双源逐字节比对测试，否则静默漂移——所有测试照样全绿，只在边缘路径暴露旧副本。

## 三、缓存与回滚纪律

- **HTML 永远不得进长缓存/immutable**；长缓存只给带版本戳的静态资源。
- 通配规则（如 `/*`）里永远不得出现 Cache-Control——一条过宽的缓存规则爆炸半径是全站。
- 长缓存上线后，JS 只能「向前回滚」（发新版本号），不能回退文件——这条必须写进发版纪律。
- 历史 JS 文件（带旧版本戳的）**永不删除、永不改名**：旧 HTML 副本可能还引用着它们。
- 「旧 HTML + 新 JS」「新 HTML + 旧 JS」的混合窗口是否存在、后果是什么，发版前必须回答。

## 四、部署配置即资产

**规则**：部署配置文件（如 Cloudflare Workers 的 wrangler.jsonc、Pages 的 _headers）与代码同等重要：

- 必须随每次推送保留在版本库；**删除它 = 部署失去配置源**（Gym 项目真实教训，见 `cases/case-gym-01-config-as-asset.md`）。
- 历史遗留文件未经确认不删——先查引用、查部署依赖，查不到就留着。
- _headers 类文件改动要评估对线上全部资源的爆炸半径，并安排上线后 curl 核验（见本篇第一节第 3 段）。

## 五、发布收尾

- 推送任务交付时写明：新提交完整哈希、变更文件数、逐文件比对结果、抽查结果、**推送完成的本地时间（精确到分钟）**——耗时统计与线上问题回溯都靠它。
- 已知遗留（不阻塞的 P2、待真机回归项）随发布报告如实列出。
- 发版相关的巡检/监控任务在发布收口后自动停用，不空转。

## 六、验证方式（发布完成定义）

- [ ] 敏感扫描零命中（本地 + 远端）。
- [ ] 远端逐文件逐字节比对全部一致。
- [ ] 线上核验项逐项有 curl/浏览器证据。
- [ ] 版本号所有同步点一致（机器断言，非人肉 grep）。
- [ ] 回滚口径明确（本批改动怎么回、回不了的写明）。
- [ ] 交付报告含提交哈希、时间戳、遗留项。
