# 规则 02：证据与裁决纪律

> 本小组一切结论建立在证据上。本篇定义：什么算证据、怎么回应别人的主张、证据与面子/文档/用户口径冲突时怎么办。

## 一、证据门槛（什么才有资格进入裁决）

**规则**：任何技术主张——无论是根因、收益数字、还是「这样改没问题」——必须满足以下两条之一，否则标记为「存疑」或「不成立」：

- **可定位**：引用代码/文档时给到 `文件 + 行号`（或精确的章节/配置项）。
- **可复现**：引用数字时给到 `测量方法 + 环境 + 样本量`，让别人能重跑出同量级结果。

**为什么**：白屏对抗中，一方把基线白屏时长「估」为 4~8 秒，另一方实测（还是更差网络路径）只有 1.6~2.9 秒——基线虚高 2~3 倍会虚高所有收益计算，直接动摇终裁可信度。估算不是不能用，是必须标注「估算」并说明口径。

**做到什么程度算够**：
- 报告里每个定量数字后面都能回答「这数哪来的」。
- 每个「代码会这样行为」的断言都能回答「哪行代码」。
- 引用别人材料时给精确出处，不写「据报道」「上文说过」。

## 二、三态回应（怎么对待别人的每一条主张）

对每一篇找茬/评审，**逐条**给出且只给出三种状态：

| 状态 | 含义 | 义务 |
|---|---|---|
| 成立 | 接受对方指出的问题 | 写明如何修正 |
| 存疑 | 证据不足，不能判 | 写明需要补什么证据、谁来补 |
| 不成立 | 反驳 | 给出依据：行号 / 可复现实验 / 对方数据内部矛盾 |

- 禁止「部分同意」这类第四态——把复合主张拆成单条再三态。
- 回应一份 N 条的找茬，产出必须恰好 N 条三态记录。条数对不上 = 漏审。

## 三、用对方的数据反驳对方（首选反驳方式）

反驳的说服力排序：**用对方自家数据证伪对方结论 > 自己重测 > 引用代码 > 逻辑推演**。真实战例：蓝方宣称「单变量实验 -54%」，红方用蓝方自己报告里的瀑布时序数据证明该实验臂捆绑了两个变量，-54% 是联合效果——一击即中，蓝方认账修正归因口径。

## 四、证据冲突时的裁决优先级

从高到低：

1. **可复现的实测**（多方独立测量一致时为最高证据）
2. **代码事实**（文件+行号可直接核对的行为）
3. **用户口径**（需求、体验、价值判断——见下条）
4. **文档记载 / 历史记录**
5. **理论推断 / 经验估算**（必须标注）

**实测 vs 文档**——「span 277」案例：某处文档写的数值是 232，但工程师与两位复核人三方独立实测一致为 277。裁决：**按可复现真实值 277 交付**，同时在交付物和源文档**双处披露差异**、在文档上加批注订正。原则：**证据诚实优于面子**——不改数据去凑文档，也不悄悄按实测交付当没事发生。详见 `cases/case-catgame-02-evidence-honesty.md`。

**实测 vs 理论推断**：全面剖析时曾从打印预览推断「打印行间隙有问题」，但用户手里有真实打印件且效果完美——实测证据压过理论推测，该项从修复范围撤销。

**阻断项 vs 用户口径**：当双签/质检的阻断项与用户明确口径冲突时，**用户口径优先**，但流程是：先把用户原话核实并落档 → 再交裁判裁决 → 按裁决执行。不能拿「用户说过」当口头挡箭牌，也不能拿内部阻断项硬顶用户。这样避免无谓返工和已发布构建作废。

## 五、裁决书的必备要素

终裁/裁判书必须包含，缺一退回：

- 逐项裁定结论 + 依据（依据可定位/可复算）。
- 最终行动清单（分批，注明硬依赖顺序）。
- 每条预期的**诚实口径**：收益数字带归因边界（「-54% 是两项优化联合效果，非单变量」）。
- **明确不做清单**及理由。
- 遗留分歧与验证路径（上线后真机回归等）。

## 六、验证方式

- [ ] 抽查报告里 3 个数字，每个都能指出测量方法或代码行号。
- [ ] 找茬回应条数 == 找茬条目数，全部三态。
- [ ] 有估算数字时，已显式标注「估算」。
- [ ] 证据与文档冲突时，双处披露而非单边静默。
- [ ] 裁决书含「明确不做」清单。
