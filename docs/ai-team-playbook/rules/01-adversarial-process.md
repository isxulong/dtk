# 规则 01：红蓝对抗标准流程

> 本小组解决「有一定复杂度、方案不唯一、错了代价高」的问题时，默认不走单人直线，走红蓝对抗。两种模式：**四段式**（一次性方案对抗，用于方案设计/根因分析）和**迭代收敛式**（多轮落地对抗，用于实施迭代）。

## 一、什么时候用（触发条件）

- 方案不唯一且选错代价高：根因分析、性能优化、新功能方案、安全敏感改动。
- 用户/上游明确要求「红蓝对抗」。
- 单次审查涉及金额、签名、不可逆操作。
- **什么时候不用**：一行修复、明确无歧义的小改动——走「实施 → 独立质检」两段即可，对抗是手段不是仪式。

## 二、四段式标准流程（方案对抗）

```
① 独立方案（红 A + 蓝 B 并行，互不沟通）
        ↓
② 交叉找茬（A 审 B、B 审 A，逐条三态）
        ↓
③ 双裁判独立评判（裁判 C/D 互不通气，通读全部材料）
        ↓
④ 终裁（主裁决人综合裁定）→ 实施 → 独立质检 → 发布
```

**第①段 独立方案**
- 双方拿到**同一份问题定义**，但必须有**差异化视角**（如架构视角 vs 实证视角），否则对抗退化为重复劳动。
- 期间**禁止沟通**。价值就在视角差异；先通气再写等于一方抄另一方。
- 交付物必须含证据：引用代码给文件+行号，引用数字给测量方法与环境。

**第②段 交叉找茬**
- 逐条审查对方报告，每条给三态之一：**成立（接受）/ 存疑（要求补证）/ 不成立（反驳）**。
- 「存疑」「不成立」必须附依据：文件+行号、可复现实验设计、或**用对方自己的数据指出其内部矛盾**（这是杀伤力最强也最受认可的方式）。
- 同时**自查认账**：对方数据推翻了自己的论断，明确写出「我认账、修正为 X」。对抗的目标是收敛不是胜负。
- 做到什么程度算够：对方报告里每一条定量主张和每一条定性论断都有三态结论，无遗漏。

**第③段 双裁判独立评判**
- 两位裁判视角错开（如技术向 + 产品体验向），**互不通气**，各自通读第①②段全部材料。
- 每个争议点必须**选边或给出修正后的第三种表述**，禁止和稀泥；依据必须来自材料中的数据/代码或裁判自己可复算的算术，不接受任何一方的裸断言。
- 裁判有权指出「双方都漏了的东西」并补入清单（真实案例：白屏对抗中「模块加载无超时兜底」是双方方案都漏的，由裁判补入并成为方案一部分）。

**第④段 终裁与落地**
- 主裁决人（主 AD）综合双方材料 + 双裁判书做终裁，产出：一句话结论、分批行动清单、每条预期的**诚实口径**（收益数字必须带归因边界）、明确不做清单。
- 终裁后进入「实施 → 独立质检 → 发布」三段，见 `rules/03`、`rules/04`。

## 三、迭代收敛式（实施对抗，定稿于 lydz 项目）

用于方案已定、需要边做边验的实施迭代：

```
AB 各自落地 → 交叉检验 → C 汇总（必须给「收敛判定」）→ AB 复核 → 未收敛则再循环
```

- **每轮 C 汇总必须显式给出收敛判定**（已收敛 / 未收敛+未决点清单），不许只合并不判断。
- **超过 3 轮未收敛，主裁决人按现有证据强制裁决收口**——对抗不是永动机，证据不足时按「可逆性更高 / 风险更小」的选项裁。
- **实施者回避对抗**：参与落地的人不做本轮对抗的裁判或找茬方，避免自己审自己。

## 四、硬纪律（违反即对抗无效）

- 对抗期间双方零沟通；裁判之间零沟通。
- 证据门槛：无文件+行号、无可复现实验的主张，找茬方有权直接标「不成立」。
- 逐条三态，禁止「总体同意、细节再聊」式模糊回应。
- 认账必须显式写出，不写视为未认账。
- 终裁书写明「明确不做」清单——砍掉什么和做什么同等重要（白屏对抗砍掉：内联模块、虚拟化、按文件粒度 bump）。

## 五、验证方式（你怎么知道这次对抗做对了）

- [ ] 双方方案是独立产出的（时间线可证：交付时间接近、结论有真实分歧点）。
- [ ] 找茬记录里每条都是三态之一且附依据，有至少一次「用对方数据反驳对方」或「认账修正」。
- [ ] 两位裁判书有观点差异（完全一样说明没有独立评判）。
- [ ] 终裁书包含：结论、分批清单、诚实收益口径、明确不做清单。
- [ ] 从问题提出到终裁，每个环节的产物都可回查（评论/文档留档）。
