# 清单：发布前检查单

> 用法：任何推送到远端 + 部署上线前逐项勾选。少一项不发布。依据见 `rules/03`、`rules/04`、`rules/05`。

## 1. 推送前

- [ ] 敏感信息扫描**零命中**（本地仓库 + 远端 tarball 双扫，模式见 `secrets-scan-checklist.md`）
- [ ] 远端 HEAD 确认未漂移（GET 确认仍是预期值），漂移则先报告不硬推
- [ ] 版本号所有同步点一致（机器断言通过，非人肉核对）
- [ ] 双数据源逐字节一致（比对测试通过）
- [ ] 全量测试换干净目录重跑全绿
- [ ] 量化验收口径达标（性能数字实测，非估算）
- [ ] 提交信息沿用仓库惯例风格
- [ ] 用 fast-forward，不 force push
- [ ] 部署配置文件（wrangler/_headers 等）仍在且本次改动已评估爆炸半径

## 2. 推送后

- [ ] 逐文件远端比对：**每个文件**逐字节一致（不只比对清单/大小）
- [ ] 抽查：新增文件在 tree 中且被正确引用；版本号各处一致
- [ ] 提交哈希已记录

## 3. 部署后线上核验（对线上真实地址，不看平台绿勾）

- [ ] HTML 响应不含长缓存/immutable
- [ ] 静态资源含预期缓存头；同一 URL 二次请求缓存命中
- [ ] 逐个静态模块核响应头；既有安全头（CSP/HSTS 等）仍在
- [ ] 线上实际渲染抽查（无头浏览器或 curl 内容抽查）
- [ ] 缓存/回滚口径确认：本批改动怎么回；「旧 HTML + 新 JS」混合窗口的后果已回答

## 4. 收尾

- [ ] 交付报告含：新提交完整哈希、变更文件数、逐文件比对结果、线上核验结果、**推送完成本地时间（精确到分钟）**
- [ ] 已知遗留（P2/待真机回归项）如实列出，不润色
- [ ] 需真机回归的事项已向用户明确提出
- [ ] 本项目巡检/监控任务已安排自动停用，不空转
- [ ] 经验回流（依据 `rules/07`）：本轮有价值的经验已回流手册（新案例进 cases/、规则变化改 rules/、清单缺口补 checklists/、反面教材进 anti-patterns.md），或已明确记录「本轮无值得沉淀的经验」
