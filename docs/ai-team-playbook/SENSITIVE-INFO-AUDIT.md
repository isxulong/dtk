# 附录：敏感信息自查清单（发布前扫描复用）

> 用途：任何文档集、代码库、分发包**对外发布前**，按本清单逐项扫描。这是「最容易意外泄露什么 + 用什么模式抓它」的对照表。执行流程见 `checklists/secrets-scan-checklist.md`，纪律见 `rules/05`。
>
> 注意：模式本身不是秘密——本附录可以公开；但它抓到的任何命中都是秘密，必须处置后重扫。

## 一、泄露类型自查表

| # | 易泄露内容 | 典型藏身之处 | 自查模式（grep/find） | 命中后处置 |
|---|---|---|---|---|
| 1 | GitHub 令牌（PAT） | 脚本、CI 配置、shell 历史、文档里的「示例命令」 | `github_pat_[A-Za-z0-9_]+`、`ghp_[A-Za-z0-9]{30,}`、`gho_[A-Za-z0-9]+`、`github_pat_` 作为词根也要查 | 吊销换新；查 git 历史是否进过库 |
| 2 | 通用 API Key / 访问令牌 | 配置文件、环境样例（.env.example 写真实值）、注释 | `sk-[A-Za-z0-9]{20,}`、`AKIA[0-9A-Z]{16}`、`xox[baprs]-`、`(?i)(api[_-]?key\|token\|secret)\s*[:=]\s*["'][^"']{8,}` | 轮换；改成占位符 |
| 3 | 私钥 | 误提交的 .pem/.key、备份目录 | `-----BEGIN`（RSA/EC/OPENSSH/PGP PRIVATE KEY 全覆盖） | 吊销对应凭据，清理历史 |
| 4 | 签名材料 | 源码包、构建目录、「顺手打包」的 zip | `find . -iname '*.keystore' -o -iname '*.jks' -o -iname '*.p12' -o -iname '*.pfx'`；`storePassword`、`keyPassword`、`signingConfig` | 签名身份作废换新（见 `cases/case-catgame-01-signing-leak.md`） |
| 5 | 密码/口令明文 | 配置文件、数据库连接串、脚本参数 | `(?i)(password\|passwd\|pwd)\s*[:=]\s*["'][^"']{4,}`；`://[^:/\s]+:[^@/\s]+@`（URI 内嵌口令） | 改密 + 改走环境变量 |
| 6 | 内部平台 ID（任务/评论/成员/文档编号） | 从内部协作平台复制来的讨论记录、任务书 | 长数字串：`[0-9]{15,20}`；结合上下文判断是否内部编号 | 删除（这类编号无脱敏价值，直接删） |
| 7 | 内部协作文档/云盘链接 | 案例叙述、参考材料章节 | `feishu\.cn`、`larkoffice\.com`、`/docx/`、`/wiki/`、`/file/`、`/drive/` | 删除；需要的公开材料换公开链接 |
| 8 | 内部工作台/平台链接 | 任务书、流程记录 | 组织内部域名（按你的组织列清单，如内部控制台、内部任务平台域名） | 删除 |
| 9 | 个人姓名、邮箱、手机号 | 作者署名、git config、测试数据、「联系人」章节 | 邮箱：`[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}`；手机号：`1[3-9][0-9]{9}`；姓名按人员名单逐词 grep | 删除或替换为角色称谓（「主裁决人」「质检官」） |
| 10 | 「去哪里取秘密」的指引 | 运维文档、「如何获取权限」章节 | 人工通读 + 关键词：`令牌在`、`密码见`、`找 XX 要`、`存放在`、`去……取` | 删除。存放位置指引 = 给攻击者画地图，比秘密本身更不能写 |
| 11 | 内网地址 / 内部域名 / 内部 IP | 配置、日志样例、文档 | `10\.[0-9]+\.`、`172\.(1[6-9]\|2[0-9]\|3[01])\.`、`192\.168\.`、内部域名清单 | 替换为示例值（如 `example.com`、`203.0.113.0/24` 文档专用段） |
| 12 | 真实用户数据/测试样本中的隐私 | 测试 fixture、截图、日志样例 | 人工审查 fixture 目录 + 截图（截图要用眼看，grep 抓不到） | 换合成数据 |

## 二、推荐扫描流程（一次发布前的完整动作）

```bash
# 1. 工作区扫描（把上面各模式合成一条，或逐条跑）
grep -rInE 'github_pat_|ghp_[A-Za-z0-9]|sk-[A-Za-z0-9]{20}|AKIA[0-9A-Z]{16}|-----BEGIN|storePassword|keyPassword' .

# 2. git 历史扫描（秘密删了当前版本还在历史里 = 没删）
git grep -nE 'github_pat_|-----BEGIN' $(git rev-list --all) -- . | head -50

# 3. 长数字串与内部链接（误报会多，人工过一遍）
grep -rInE '[0-9]{18,20}' . | grep -vE 'node_modules|\.git/'
grep -rInE 'feishu\.cn|larkoffice\.com' .

# 4. 文件类型扫描（签名材料、密钥文件、环境文件）
find . -type f \( -iname '*.keystore' -o -iname '*.jks' -o -iname '*.p12' -o -iname '*.pfx' -o -iname '*.pem' -o -iname '.env*' \)

# 5. 分发包扫描（解开产物包再扫一遍——打包脚本可能带进了工作区之外的东西）
```

## 三、三条最容易被忽略的原则

1. **删了当前版本 ≠ 删干净**：git 历史、远端 tarball、旧分发包里都可能有残留——所以要求本地 + 远端双扫。
2. **「示例」也要扫**：文档里写「示例命令」时粘贴真实命令是最常见的泄露路径——示例一律用占位符（`<TOKEN>`、`your-token-here`）。
3. **截图与图片要眼看**：grep 抓不到图片里的令牌、内部链接、人名——对外材料里的每张图人工过一遍。

## 四、本清单自身的元规则

- 本清单可以公开（模式不是秘密）；但任何一次扫描的**命中详情**按秘密处理。
- 组织特有的内部域名、ID 格式、人员名单要由使用方补进「按你的组织改」的位置——补进去的那份内部版清单本身不要公开。
